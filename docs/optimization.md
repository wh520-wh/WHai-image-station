# 项目优化与前端升级

更新日期：2026-10-13。

采用 QML / Qt Quick 作为默认前端，保留 Python 的业务、网络与存储层。现有性能问题集中在界面线程中的等待、全量控件创建、任务调度和文件处理。先修复这些问题，再让功能开发沿独立页面与服务模块推进，可以保留旧数据和现有适配器的价值。后续若测量发现明确的 CPU 热点，再针对那个模块选择其他语言；服务商的生成等待时间需要在真实使用时单独测量。

| 范围 | 已完成的改造 |
| --- | --- |
| 前端结构 | 创作、作品库、提示词、来源、工具、设置六个独立 QML 页面，共用组件与主题；页面按需加载并保留未保存输入 |
| 动效与反馈 | 即时按压反馈、克制的转场、开屏与骨架屏、深色外观、系统和用户的减少动态效果设置；主要操作固定在表单底栏 |
| 界面响应 | 异步操作通过 Qt 推进，文件压缩、解压和图片读取交给后台；异步计时器在空闲时停止 |
| 任务调度 | 按并发额度分派，保留等待任务的可见性和取消能力；独立数据库连接、完整状态与失败诊断 |
| 作品库 | 数据库搜索后分页，GridView 按视口创建与复用图片控件，限制预览解码尺寸；多图查看、另存、复制、批量操作 |
| 来源与模型 | OpenAI、Gemini、FLUX.2、MiniMax 预置及专用请求格式；官方退役模型停用，自定义来源保留；参数按模型能力显示 |
| 模板与流程 | 恢复来源、模型和参数；流程支持顺序生成、暂停、继续和停止，重启与导入后等待手动运行 |
| 数据迁移 | schema v3 原位迁移；事务隔离并发操作；备份含实际图片、模型和流程，可携带密码加密密钥跨机器恢复 |
| 分发 | 统一 build.py 与 spec，收集实际需要的 Qt 模块，避免外部工具的同名 DLL 污染；目录分发省去每次启动解压 |

当前回归包含 242 项离线测试，覆盖模拟 HTTP、队列、迁移、UI 和图片操作；Ruff 与 Pyright 无错误。源码和打包程序的六个页面均完成离线加载检查；界面截图检查包含浅色、深色、开屏与小窗口布局。

同一台机器的两次隔离启动检查中，正式版从应用初始化到界面就绪约 1.9–2.7 秒。该值包含 QML 和测试数据库初始化，未覆盖进程加载之前的时间，也不代表所有机器的冷启动或 GPU 帧率。分发目录由最初全量收集 Qt 的约 498 MB 缩至约 180 MB；这是磁盘占用，不能换算成运行内存节省。

Logo 采用图片画框与生成光芒的组合，统一侧栏、开屏、设置页、窗口和 EXE 图标。PNG 与多尺寸 ICO 随程序分发；打包检查核对了 EXE 内的七个图标资源与 ICO 内容一致。

没有使用真实密钥调用付费生图接口。账号权限、区域限制、限额、真实返回质量和计费行为由使用者之后验证，离线测试无法证明这些条件。

后续添加工具可新增 `src/ui/pages` 页面，在 `Main.qml` 的 pages 列表注册入口；共用组件放入 components，操作通过 StudioBridge 的信号和槽调用 Python 服务。新增 Qt 模块需更新打包白名单；改变存储结构需增加数据库迁移和对应测试。旧 Widgets 界面保留为对照入口。
