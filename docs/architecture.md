# 模块职责与扩展约定

应用保留 Python 业务逻辑与 QML 界面。模块按照变化原因划分：图片文件规则、参考图数据兼容、历史记录、任务运行和 Qt 展示各有明确归属。

| 模块 | 负责 | 调用方不应承担 |
| --- | --- | --- |
| `src/managers/image_assets.py` | 有界读图、格式校验、参考图文件副本、缩略图、转换/缩小/压缩 | SQL、QML 状态、模板字段兼容 |
| `src/managers/reference_manager.py` | 顶层和 params 内参考字段的兼容读取/改写、保留设置、旧引用迁移 | ZIP 编码、页面反馈、服务商请求 |
| `src/managers/migration_manager.py` | 归档版本、选择项、冲突策略、ZIP 去重、路径恢复与失败回滚 | 复制参考字段协议、依赖某个服务商生成缩略图 |
| `src/managers/history_manager.py` | 历史读取/删除、本地处理记录的构造与保存、识别本地处理记录 | Qt 属性、图片处理控件 |
| `src/managers/queue_manager.py` | 事件唤醒、并发额度、任务完成等待、状态副本、工作线程退出 | 页面布局和轮询计时 |
| `src/managers/task_chain_executor.py` | 顺序执行、暂停/继续/停止、通过队列通知等待终态 | 直接轮询跨线程任务字段 |
| `src/desktop.py` | Qt 属性/信号/槽、文件选择、异步操作状态、展示与导航 | 图片编码细节、本地处理历史表字段 |
| `src/ui/pages/ToolsPage.qml` | 图片处理与生成流程的切换 | 工作流编辑细节和图片处理逻辑 |

`ImageToolsPanel.qml` 和 `WorkflowPanel.qml` 分别承载两种工具体验，共用 Theme、按钮、输入框、图标及减少动态效果设置。流程身份由正在编辑的流程派生，保留已保存设置的条件只定义一次。

## 初始化与关闭

`ImageMakerApp._async_init()` 连接数据库后执行一次旧参考图迁移，再初始化管理器与界面。HistoryManager 和 StudioBridge 不重复扫描。独立调用管理器的程序若需要迁移旧数据，应在初始化阶段显式调用 `migrate_references(db)`。

队列事件来自后台线程，Qt 通过排队信号在 GUI 线程接收。队列空闲时等待事件；流程等待任务完成通知。取消一个观察者不取消生成任务。预览的耗时计时与业务事件分开，仅在选中的任务进行中时启用。流程管理器负责关闭自己的执行线程，界面不读取私有线程集合。

## 图片与参考图

`ImageInfo` 和 `ImageEditInfo` 定义文件模块的返回字段；QML 的 URL、忙碌状态和落库状态由桥接层补充。处理始终生成新文件，保持原图；失败清理半成品。方向、透明度和兼容的颜色配置由文件模块处理。

参考图副本按内容散列命名，发布文件时在进程内同步，只有实际创建副本的操作拥有新增文件的回滚权。生成作品与参考副本是不同文件；删除作品不会破坏已保留的引用。参考副本暂不自动回收。

备份按同一文件路径缓存归档成员，再按内容去重，缓存不保留大图片字节。导入跟踪本次创建的文件，失败时清理它们并回滚数据库，已有文件保留。旧备份缺少参考图本体时，保留路径供用户重新选择。

本地工具记录使用稳定的 `local_image` 类型；展示文字独立。复用本地处理记录进入图片工具，不把输出品质等参数灌入生图草稿。

## 添加一种本地处理

先在 `image_assets.process_image()` 增加明确的处理分支、参数校验与结果规则，再在 ImageToolsPanel 添加对应操作。历史记录通过 `HistoryManager.save_local_edit()` 保存，桥接层继续负责执行状态。若需要新增参数，应同步更新调用契约与 UI，不先建设插件框架。

验证应覆盖真正的行为：原图保留、格式/尺寸/方向/透明度、失败清理、历史记录和真实 QML 操作。修改参考图规则时同时验证保存、跨目录恢复、删除原作品及失败回滚。完成必要检查后，再进入打包验证。
